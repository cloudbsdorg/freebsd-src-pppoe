## 10. Phase 8: Comprehensive Testing Framework (`pppoetest`)

A production-grade testing tool for validating PPPoE load balancer functionality, accuracy, and performance. Written in C++ with no external dependencies.

### 10.1 Overview

The `pppoetest` tool provides:

| Feature | Description |
|---------|-------------|
| **Session Accuracy Tests** | Verify session distribution matches configured algorithm |
| **Session Affinity Tests** | Verify sessions stay on assigned worker |
| **Governor Scaling Tests** | Verify auto-scaling triggers correctly |
| **File Transfer Tests** | Stream files with checksum verification (iperf3-style) |
| **Real-time Display** | Tabular stats with live updates (like iperf3) |
| **Man Page** | Full documentation with examples (mdoc + markdown) |
| **Shell Completions** | Bash, Zsh, and Tcsh support |
| **Diagnostic Mode** | Passive observation of production systems (default) |
| **Production Safe** | Does not create sessions unless explicitly requested |

### 10.2 Architecture


### 10.5 File Transfer Test Implementation

The transfer test uses PPPoE sessions to stream data and verify integrity:

#### 10.5.1 Checksum Algorithm

| Algorithm | Speed | Use Case |
|-----------|-------|----------|
| **CRC32** | Fastest | Default, good for error detection |
| **Fletcher32** | Fast | Alternative to CRC32 |
| **MD5** | Medium | Legacy compatibility |
| **SHA256** | Slow | Cryptographic verification |

#### 10.5.2 Transfer Protocol

```c
struct transfer_header {
    uint32_t    magic;          // 0x50505045 ('PPPE')
    uint32_t    sequence;        // Packet sequence number
    uint32_t    block_num;       // Block number
    uint32_t    block_size;      // Size of this block
    uint32_t    total_blocks;    // Total blocks in transfer
    uint64_t    file_offset;     // Offset in file
    uint64_t    file_size;       // Total file size
    uint32_t    checksum_type;   // 0=CRC32, 1=Fletcher32, 2=MD5, 3=SHA256
    uint32_t    checksum_len;    // Length of checksum
    uint8_t     checksum[];      // Checksum value
    uint8_t     data[];         // Payload data
};
```

#### 10.5.3 Accuracy Verification

| Metric | Description | Pass Criteria |
|--------|-------------|---------------|
| **Block Count** | All blocks received | `received == total_blocks` |
| **Sequence** | No missing packets | `seq[i] == i` for all i |
| **Checksum** | Data integrity | `checksum(data) == expected` |
| **Ordering** | Blocks in order | No sequence gaps |
| **Timing** | Transfer rate stable | `stddev(rate) < 20%` |

```c
struct accuracy_result {
    int                 worker_id;
    enum worker_state  state;
```

##### 10.11.1.3 Terminal Detection

```c
// Automatic color support detection
static bool supports_color(FILE *fp) {
    // Check if stdout is a terminal
    if (!isatty(fileno(fp)))
        return false;
    
    // Check TERM environment variable
    const char *term = getenv("TERM");
    if (term == NULL)
        return false;
    
    // Known terminals that support ANSI colors
    static const char *color_terms[] = {
        "xterm", "xterm-256color", "xterm-color",
        "screen", "screen-256color", "tmux", "tmux-256color",
        "rxvt", "rxvt-unicode", "rxvt-unicode-256color",
        "linux", "konsole", "gnome", "vt100", "vt220",
        "dumb"  // Even dumb supports colors if forced
    };
```

### 10.12.2 Communication Channels

#### 10.12.2.1 Control Channel (TCP)

| Property | Value |
|----------|-------|
| **Protocol** | TCP |
| **Default Port** | 9001 |
| **Purpose** | Test control, coordination, status updates |
| **Encryption** | None (use SSH tunnel for security) |
| **Heartbeat** | Every 5 seconds |

#### 10.12.2.2 Data Channel (PPPoE)

| Property | Value |
|----------|-------|
| **Protocol** | PPPoE over physical interface |
| **Purpose** | Actual test data transfer |
| **Verification** | Checksums computed per block |
| **Bidirectional** | Yes - both sides can send/receive |

Events are sent over the control channel as JSON messages for coordination.

## 10.13 Diagnostic Mode (Production Safe)

The `diagnose` mode is the **default** mode for `pppoetest`. It provides passive observation of existing PPPoE load balancer state without creating any sessions or modifying anything. This makes it safe to run on production systems.

### 10.13.1 Design Philosophy

| Principle | Description |
|-----------|-------------|
| **Read-Only by Default** | No session creation unless `-m create` or `-m mixed` specified |
| **Safe Defaults** | 20% imbalance threshold, 5s monitoring interval |
| **Non-Invasive** | Only reads sysctls and netgraph state |
| **Configurable** | All thresholds and behaviors can be overridden |

### 10.13.2 Diagnostic Commands

| Command | Short | Description |
|---------|-------|-------------|
| `--show-workers` | `-s` | Display all workers with state, sessions, CPU |
| `--show-sessions` | `-S` | Display all active sessions with details |
| `--show-governor` | `-g` | Display governor state, thresholds, decisions |
| `--health-score` | `-H` | Calculate and display overall health score |
| `--check-affinity` | | Detect session affinity violations |
| `--check-balance` | | Check load balance across workers |
| `--monitor` | | Enable real-time monitoring mode |

### 10.13.13 Production Safety Features

| Feature | Description |
|---------|-------------|
| **No Session Creation by Default** | Must use `-m create` or `-m mixed` to create sessions |
| **Read-Only Sysctls** | Only reads state, never modifies (except with explicit flags) |
| **Non-Blocking Queries** | All diagnostic commands complete quickly |
| **Safe Error Handling** | Fails gracefully if kernel module not loaded |
| **Clear Warnings** | Always shows when crossing threshold boundaries |
