# Load Balancer Node Design

## 2.0.1 High-Level Architecture

```
+-------------------------------------------------------------+
|                    Ethernet Interface                        |
|                      (ng_ether node)                         |
+----------------------------+--------------------------------+
                             |
                             v
+-------------------------------------------------------------+
|              ng_pppoe_lb (Load Balancer Node)                |
|  - Distributes packets to worker nodes based on session hash |
|  - Handles discovery phase (PADI) broadcast                  |
|  - Manages session-to-node mapping table                     |
+--+-----------+-----------+-----------+-----------+----------+
   |           |           |           |           |
   v           v           v           v           v
+------+   +------+   +------+   +------+   +------+
|pppoed|   |pppoed|   |pppoed|   |pppoed|   |pppoed|
|  #0  |   |  #1  |   |  #2  |   |  #3  |   |  #N  |
+------+   +------+   +------+   +------+   +------+
```

---

## 2.0.2 Key Design Principles

1. **Minimal changes to existing code:** Reuse `ng_pppoe` as-is, add new components
2. **Leverage existing netgraph parallelism:** Each worker node runs on different threads
3. **Session affinity:** All packets for a given session go to the same worker node
4. **Incremental deployment:** Can start with 1 node (current behavior) and scale up
5. **Auto-scaling support:** Governor monitors load and adjusts worker count automatically

---

## 2.0.3 Session Affinity

The load balancer maintains a session map that tracks which worker is handling each session:

```c
struct sess_map_entry {
    uint16_t          session_id;       // PPPoE session ID
    int               worker_id;         // Worker handling this session
    struct timeval    last_activity;    // Last packet activity
    LIST_ENTRY(sess_map_entry) entry;   // Hash chain
};
```

When a packet arrives:
1. Extract session ID from PPPoE header
2. Look up session in hash map
3. Forward to appropriate worker node

---

## 2.0.4 Load Balancing Algorithms

### Round-Robin (Algorithm 0)
- Simple rotation through workers
- Good for even session distribution
- No session affinity consideration

### Hash-Based (Algorithm 1)
- Hash session ID to select worker
- Consistent mapping for same session
- Default recommended algorithm

### Least-Loaded (Algorithm 2)
- Select worker with fewest active sessions
- Dynamic load balancing
- Higher overhead for selection
